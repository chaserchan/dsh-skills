# README 骨架模板（按项目类型）

用法：先确定项目类型 → 取对应骨架 → **裁剪**（删掉对当前项目无意义的节）→ 按 SKILL.md 四步法填充。骨架是起点不是终点。

## A. npm 库 / 插件包（sindresorhus 流派）

```
# 包名 + 徽章行（npm version / CI / downloads / license，flat 统一色）

> 一句 tagline（类别 + 差异）

## Install
```bash
npm install <pkg>
```

## Usage（最小可运行示例，先于一切解释；重要时给预期输出）
```js
import ... from '<pkg>'
```

## API / Options（只放高频用法；低频外链 docs）
## 对比（有替代品时：表格或要点）
## TypeScript（库提供类型时）
## 贡献 / License
```

## B. DSH / 平台插件（本环境高频）

```
# 插件名 + 徽章（npm / Gitee / GitHub）

> 一句：插件做什么 + 在哪出现（如"在设置-通用设置新增一栏…"）+ 生效范围

## 安装与启用（三步，全部可复制）
1. dsh plugin --profile web add <pkg>
2. cordis.patch.yml 追加启用行（给完整 YAML 片段）
3. 重启 dsh web

## 行为（留空=停用、热加载、卸载方式——读者最关心的三个事实）
## 配置（settings namespace / 字段 / 上限）
## 开发（本地 link 安装注意事项）
## 发布（维护者命令）
## 设计边界（做了什么、不做什么）
```

## C. CLI 工具

```
# 名称 + 徽章 + tagline

## 安装（包管理器多路）
## 快速开始（第一条命令 + 屏幕录制 GIF 最佳）
## 命令参考（表格：命令 / 说明 / 示例）
## 配置（配置文件/环境变量，给示例文件）
## FAQ / 退出码 / 常见错误
## License
```

## D. Web 服务 / UI 应用

```
# 名称 + banner + 徽章

> tagline
> 项目截图 / demo GIF（视觉即卖点，放首屏）

## 特性（benefit 导向，配小图/GIF 每个特性）
## 快速开始（clone → install → run；多环境用可折叠块：dev/prod/docker）
## 技术栈 / 架构（用图；详细架构放 ARCHITECTURE.md 并链接）
## 文档 / Demo 链接
## 贡献 / 社区 / License
```

## E. 内部工具 / 工作区仓库

```
# 名称

> 一句话用途（服务对象：团队/自己）

## 环境要求（版本、依赖、密钥）
## 安装与运行（精确到命令）
## 目录结构（一图/一表）
## 常见任务（按任务命名：怎么跑测试、怎么发布、怎么加新插件）
## 约定（命名、提交规范、分支）
```

## 通用收尾三件套

- **License**：开源必带；内部可省。
- **贡献指南**：开源 + 期待贡献才放。
- **致谢/致谢数据**：有真实数据（star、使用者）才放，不编造。
